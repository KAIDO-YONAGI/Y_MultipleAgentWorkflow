## 1. 适用时机

- 同一套规则在多个文档里各有一份。
- 入口文件越写越长，开始与 Router 重复。
- 读者先读到资源清单，读不到工作方式。
- 巡检发现引用、清单或规则互相冲突。

## 2. 单一来源

- 行为准则只存在一份，通常放在项目根的规则文档或根 Router。
- 其他文档只写引用，不复制条目。
- 删除副本前先检索取证：用准则里的标志性语句检索全仓，确认命中只剩一处。
- 只有在文档结构要求时才保留第二份，并写明理由。

## 3. 入口薄化

- 入口保留导航表和三到五条铁律，其余细则移入权威库的单份文档。
- 铁律留在入口的理由：入口位于每一轮对话的基线上下文，库文档只在被读取后才进入上下文。
- 去重条件：同类入口文件去首尾空白后内容完全一致才会折叠渲染；一行式指针与全文副本内容不同，不会折叠。
- 两种形态都成立：接受一行额外预算，或接受两份文件同步维护。选定后写进文档。

## 4. 章节顺序

根 Router 统一采用以下七个章节，按此顺序排列：

1. 维护规则
2. 工作方式
3. 权威顺序
4. 项目验证
5. 功能域路由
6. 功能域导航
7. 当前实现入口

维护规则紧跟标题和元信息，工作方式与权威顺序位于业务正文开头。项目验证只声明模式和独立指南路径，不展开项目命令。功能域路由按触发词或目标指向必读文档；功能域导航只列各功能域 Router；当前实现入口只保留少量已核验的代码、资源或运行入口。

根 Router 不设置“文档索引”章节，不维护覆盖全库的文档清单或全量索引表格。详细文档索引由各功能域 Router 就近维护，文档 ID、状态、更新时间和核验信息保留在对应文档或所属功能域索引中。功能域路由与功能域导航表继续保留。

维护规则之后可保留项目定位和单一规则文档的引用。新建和维护现有工作流都遵循此结构；已经取消全量索引表格的根 Router 不得重新补回。

各类 Router、Guide/Design、DeveloperLog、Proposal/Reference 都把本文件的维护规则放在标题与元信息之后、正文之前，说明更新触发条件和证据归属，按需引用共享细则。Guide 在维护规则之后提供链接到小标题的文档内目录，先读目录再读所需章节；改标题时同步跳转链接。这个目录只服务当前文件，不是全库文档索引。

了解当前情况优先读取 Guide 的相关章节。确需读取日志时，先按日期、标题或任务关键词定位，只提取最近一天或两天内的相关条目，禁止把整个日志载入上下文。近期没有相关记录时回到 Guide；仅在任务需要历史追溯时定向读取更早条目。读取范围与存储保留分开处理，不因此裁剪日志历史。

## 5. 矛盾清理

1. 盘点：逐条列出，编号，写清位置与冲突对象。
2. 取证：每条给出文件与行号、命令输出。引用不存在的文件本身就是矛盾。
3. 询问：把条目做成可勾选清单交给用户，由用户决定删除项。未勾选的保留。
4. 落地：按确认项逐条修改。语义不变的重复条目合并可以一次完成。
5. 复验：检索标志语句、核对行数、核对目录实况。
6. 范围外事项只记一行，不展开、不建议修。

## 6. 引用与清单验证

- 引用其他文档前验证存在。不存在就删掉引用，不保留死链。
- 清单类章节与目录实况核对：缺项补进清单，或删掉整段改为指向权威清单。
- 结论保留命令与输出作为证据。

## 7. 结构整理细则

- 同一约束的重复条目合并为一条。
- 悬空的引导句删除或补成完整条目。
- 括号解释改为正文说明。
- 准则与行为规则冲突时给准则加适用范围，不改用户给定的措辞。

## 8. 验收

- 标志语句全仓检索只剩一处。
- 入口达到目标行数，细则不在入口。
- Router 章节顺序符合第 4 节。
- 各类文档的维护规则位于标题和元信息之后、正文之前。
- Guide 的小标题目录可跳转，读取时先目录后相关章节。
- 日志默认只读取最近一天或两天的相关条目，不整份载入，不因此删除历史。
- 每条被删内容都有取证依据，删除项与用户确认一致。
