# 文档维护与收敛方法

文档 ID：`WF-DOC-MAINTENANCE`
状态：`Active`
最后更新：`2026-10-20`
方法适用范围：跨项目

初始化负责建立结构，本文负责结构建立之后的收敛：单一来源、入口薄化、章节顺序、矛盾清理和引用验证。本文属于 Skill 的维护阶段方法。

## 1. 适用时机

- 同一套规则在多个文档里各有一份。
- 入口文件越写越长，开始与 Router 重复。
- 读者先读到资源清单，读不到工作方式。
- 巡检发现引用、清单或规则互相冲突。

## 2. 单一来源

- 行为准则只存在一份，通常放在项目根的规则文档或根 Router。
- 其他文档只写引用，不复制条目。
- 删除副本前先检索取证：用准则里的标志性语句检索全仓，确认命中只剩一处。
- 只有在文档结构要求时才保留第二份，并写明理由。

## 3. 入口薄化

- 入口保留导航表和三到五条铁律，其余细则移入权威库的单份文档。
- 铁律留在入口的理由：入口位于每一轮对话的基线上下文，库文档只在被读取后才进入上下文。
- 去重条件：同类入口文件去首尾空白后内容完全一致才会折叠渲染；一行式指针与全文副本内容不同，不会折叠。
- 两种形态都成立：接受一行额外预算，或接受两份文件同步维护。选定后写进文档。

## 4. 章节顺序

根 Router 的推荐顺序：

1. 工作方式
2. 权威顺序
3. 项目验证
4. 功能域路由
5. 功能域导航
6. 当前实现入口
7. 文档索引
8. 维护

工作方式与权威顺序回答怎么干活，放在最前。当前实现入口与文档索引是查表用的资源清单，放在正文之后。

## 5. 矛盾清理

1. 盘点：逐条列出，编号，写清位置与冲突对象。
2. 取证：每条给出文件与行号、命令输出。引用不存在的文件本身就是矛盾。
3. 询问：把条目做成可勾选清单交给用户，由用户决定删除项。未勾选的保留。
4. 落地：按确认项逐条修改。语义不变的重复条目合并可以一次完成。
5. 复验：检索标志语句、核对行数、核对目录实况。
6. 范围外事项只记一行，不展开、不建议修。

## 6. 引用与清单验证

- 引用其他文档前验证存在。不存在就删掉引用，不保留死链。
- 清单类章节与目录实况核对：缺项补进清单，或删掉整段改为指向权威清单。
- 结论保留命令与输出作为证据。

## 7. 结构整理细则

- 同一约束的重复条目合并为一条。
- 悬空的引导句删除或补成完整条目。
- 括号解释改为正文说明。
- 准则与行为规则冲突时给准则加适用范围，不改用户给定的措辞。

## 8. 验收

- 标志语句全仓检索只剩一处。
- 入口达到目标行数，细则不在入口。
- Router 章节顺序符合第 4 节。
- 每条被删内容都有取证依据，删除项与用户确认一致。
